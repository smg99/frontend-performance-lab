# Dogfooding Protocol

For every future dogfooding session, follow this strict protocol:

## Protocol Steps

1. **Run `performance_audit`** on the target component.
2. **Read the engineering report** generated by the tool.
3. **Accept or reject each finding** by manually inspecting the code and evaluating the tool's claims.
4. **Record false positives** in `FALSE_POSITIVES.md`.
5. **Record missing detections (false negatives)** in `FALSE_NEGATIVES.md`.
6. **Record desired analyzer rules** based on missed detections in `FEATURE_REQUESTS.md`.

## Review Checklist

For every analyzed component, answer the following questions:

- Was the diagnosis correct?
- Were the explanations understandable?
- Were the recommendations actionable?
- Were priorities correct?
- Was anything confusing?
- Would a junior engineer understand this?
- Would a senior engineer agree with the findings?

## Metrics Tracking

Track the following metrics across dogfooding sessions to measure product maturity:

- **False Positive Rate:** (False Positives / Total Findings)
- **False Negative Rate:** (Missed Issues / True Issues)
- **Average Confidence:** Average confidence score of reported findings.
- **Average Report Length:** Lines or word count.
- **Time To First Insight:** Time taken from opening the component to realizing an actionable fix.
- **Developer Satisfaction:** Subjective rating (1-10) of the overall experience.
