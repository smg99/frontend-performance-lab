# Core Values

These values are the foundation of every engineering, product, and business decision made within Frontend Performance Lab.

If a decision conflicts with these values, the values take precedence.

---

# 1. Developer Trust Above Everything

Trust is the hardest thing to earn and the easiest thing to lose.

Every recommendation generated by FPL should increase developer confidence.

We would rather miss a possible optimization than confidently report something that cannot be justified.

Every release should make developers trust us more than the previous release.

---

# 2. Deterministic Before Intelligent

Artificial Intelligence is powerful.

Deterministic engineering is trustworthy.

Whenever deterministic analysis can prove something, that result always becomes the source of truth.

AI exists to:

- explain
- prioritize
- educate
- summarize
- communicate

AI never invents engineering facts.

---

# 3. Local First

Developer source code belongs to the developer.

FPL performs analysis locally whenever possible.

Cloud services may enhance the experience but must never become mandatory for the core product.

Privacy is a permanent product principle.

---

# 4. Engineering Over Marketing

We optimize for engineering quality.

Not social media attention.

Not GitHub stars.

Not hype.

Every feature should solve a real engineering problem.

We would rather build one exceptional feature than ten average ones.

---

# 5. Education Creates Better Engineers

Every warning should teach.

Every report should explain.

Every recommendation should improve understanding.

Developers should become better engineers simply by using FPL regularly.

---

# 6. Evidence Drives Evolution

Features are not invented.

They are discovered.

Every analyzer rule, diagnostic, plugin, report, and workflow should originate from evidence collected through:

- Dogfooding
- Production repositories
- Benchmarks
- False positives
- False negatives
- Community feedback

If evidence does not exist, the feature should wait.

---

# 7. Build Platforms, Not Features

Individual features create products.

Platforms create ecosystems.

Every major subsystem should be designed so other developers can extend it without modifying the core engine.

The plugin ecosystem is more important than any individual plugin.

---

# 8. Simplicity Wins

The best engineering solution is usually the simplest one that remains correct.

Complexity should only be introduced when it clearly produces long-term value.

Every unnecessary abstraction becomes future maintenance.

---

# 9. Quality Is Continuous

Quality is not a phase.

Quality exists throughout development.

Every pull request should leave the repository in a better state than before.

Broken windows accumulate.

We fix them immediately.

---

# 10. Long-Term Thinking

Frontend Performance Lab is being built for decades, not months.

Every architectural decision should consider:

- maintainability
- extensibility
- readability
- performance
- developer experience

Short-term convenience must never compromise long-term sustainability.

---

# 11. Community Multiplies Innovation

The best ideas may come from contributors outside the core team.

We welcome improvements.

We document decisions.

We encourage experimentation.

We review respectfully.

Open source succeeds through collaboration, not ownership.

---

# 12. Never Stop Improving

Every repository audited...

Every false positive discovered...

Every benchmark executed...

Every plugin published...

Every community discussion...

makes FPL better.

Continuous improvement is not an activity.

It is our culture.
