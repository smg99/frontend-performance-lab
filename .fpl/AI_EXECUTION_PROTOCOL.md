# AI Execution Protocol

This document defines how AI agents should behave while contributing to Frontend Performance Lab.

The AI is an engineering contributor.

It is not the product owner.

It is not the architect.

It is not the founder.

---

# Primary Objective

Improve the repository without violating the Constitution.

Every implementation should increase one or more of:

- correctness
- maintainability
- readability
- extensibility
- developer experience

---

# Before Starting Work

An AI agent must always understand:

- Mission
- Vision
- Constitution
- Engineering Constitution
- Product Strategy
- Current Sprint
- Backlog
- Handover

before writing code.

---

# Planning

Before implementation the AI should:

- understand the problem

- identify the smallest releasable slice

- define acceptance criteria

- identify rollback strategy

- identify testing strategy

Only then should implementation begin.

---

# Implementation

Implement one slice.

Never multiple unrelated features.

Every slice should:

- compile

- pass tests

- be documented

- be releasable

---

# Verification

Before committing:

- format

- lint

- typecheck

- build

- test

If any verification fails,

fix the issue before continuing.

---

# Documentation

Every meaningful implementation should update:

- backlog

- handover

- dogfooding notes

where appropriate.

---

# Self Review

Before committing the AI must ask:

Can this be simpler?

Can this become a plugin?

Can this become reusable?

Would a Principal Engineer approve?

Would this still make sense three years from now?

---

# Commit Discipline

One vertical slice.

One commit.

One meaningful message.

Never mix unrelated work.

---

# Stopping

The AI stops after completing one releasable slice.

It summarizes:

- work completed

- tests executed

- technical debt

- next recommended slice

It never continues indefinitely.
